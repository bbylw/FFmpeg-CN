## 说明

本文档描述 libavformat 库提供的格式（混流器 muxer 与解流器 demuxer）：解流器读取特定类型文件中的多媒体流，混流器负责写入。构建时默认全部启用，可 `--list-demuxers`/`--list-muxers` 查看、`--enable-demuxer=X` 等增删；工具的 `-formats` 显示当前构建的合并列表。

## 格式选项

libavformat 提供可设置于所有混流器与解流器的通用全局选项，另有各组件专属的私有选项；设置方式为 `-选项 值` 或 `AVFormatContext`/`libavutil/opt.h` API。常用通用选项（完整列表见官方手册 [https://ffmpeg.org/ffmpeg-formats.html](https://ffmpeg.org/ffmpeg-formats.html)）：

| 选项 | 说明 | 默认值 |
| --- | --- | --- |
| `probesize` | 探测流信息分析的数据字节数，越大越准但延迟升高，不小于 32 | 5000000 |
| `fflags` | 如 `genpts`（补生成 PTS）、`discardcorrupt`、`fastseek` | 无 |
| `analyzeduration` / `max_probe_packets` | 探测时长（微秒）/ 最大探测包数 | 无 |
| `rtbufsize` | 实时设备输入的 RingBuffer 上限 | 无 |
| `max_delay` | 最大写入时延（微秒） | 无 |
| `flush_packets` | 每包后刷新 I/O，0 可显著加速普通文件写 | 1 |

格式流限定符可按属性选取流，语义由 `avformat_match_stream_specifier()` 定义，详见官方 [Stream specifiers](https://ffmpeg.org/ffmpeg-formats.html#Format-stream-specifiers-1) 一节。

## 常用容器详解

### MP4 / MOV / QuickTime 家族

解流器 `mov/mp4/3gp` 读取 QuickTime 与 ISO-BMFF（ISO/IEC 14496-12、JPEG 2000 Part 12）家族，注册扩展名：mov、mp4、m4a、3gp、3g2、mj2、psp、m4b、ism/ismv/isma、f4v。安全相关选项：`enable_drefs`（加载外部轨道，默认关闭）、`use_absolute_path`（绝对路径外部轨道，默认关闭）、`seek_streams_individually` 等；Audible AAX 加密文件可给出 4 字节激活密钥解密。

混流器家族：`mov`、`mp4`、`3gp`、`3g2`、`f4v`、`ipod`、`ismv`（Smooth Streaming）、`psp`，均基于 ISO-BMFF box 结构。常用选项：`brand` 覆盖主品牌、`movflags` 开关集、`moov_size` 预留头部空间、`encryption_scheme cenc-aes-ctr` 加密等。

`-movflags` 最重要用法：`+faststart` 把 moov 移到文件头便于边下边播（等价于事后 qt-faststart）；另有 `default_base_moof`、`delay_moov`、`disable_chpl`（关 Nero 章节）等。

示例（官方）：实时向 IIS 推 Smooth Streaming：

```sh
ffmpeg -re <normal input/transcoding options> -movflags isml+frag_keyframe -f ismv http://server/publishingpoint.isml/Streams(Encoder1)
```

### 碎片化 ISO-BMFF（fMP4）

`mov`、`mp4`、`ismv` 支持碎片化：普通 MOV/MP4 把全部包元数据集中存放（通常在文件尾）；碎片文件则把包与各自元数据分存在若干 fragment 中。优点是写入中断文件仍可解码（普通 MP4 未正常收尾则不可用），且写长文件时不必在内存中记住每个包；代价是兼容性稍差。通过下列任一选项开启：`frag_duration`（按微秒切）、`frag_size`（按字节切）、`min_frag_duration`（下限，须同时满足）、`-movflags +frag_keyframe`（遇关键帧切）、`+frag_custom`。`movflags` 还有 `cmaf`（CMAF 兼容输出）、`dash`（DASH 兼容分片 MP4）等模式。

### Matroska / WebM

`matroska` 混流器同时实现 Matroska 与 WebM 规范。元数据：`title`（单轨标题，附件映射为 FileDescription）、`language`（ISO-639-2/B，如 `fre` 或 `fre-ca`）、`stereo_mode`（3D 布局，如 `left_right`、`anaglyph_cyan_red`）。官方示例（3D WebM）：

```sh
ffmpeg -i sample_left_right_clip.mpg -an -c:v libvpx -metadata stereo_mode=left_right -y stereo_clip.webm
```

常用选项：`reserve_index_space`（在头部预留簇索引/clues 空间，便于流式播放时文件头即带 seek 索引）。WebM 直播分块用 `webm_chunk`，清单配合 `webm_dash_manifest`。

### AVI

`avi` 为微软专有格式（后经 Open DML 规范化），播放器差异大，可能需调选项保证兼容：`flipped_raw_rgb`（自下而上裸 RGB 存正高度，需先自行 vflip）、`reserve_index_space`、`write_channel_scores` 等。

### MPEG-TS

解流器：`resync_size`（重同步上限，默认 65536）、`skip_unknown_pmt`、`fix_teletext_pts`（用 PCR 覆写字幕时间戳，默认 1）、`scan_all_pmts`（是否扫描合并全部 PMT）、`ts_packetsize`（只读，探测到的包长）。

混流器实现 ISO 13818-1 与部分 ETSI EN 300 468，识别元数据 `service_provider`（默认 FFmpeg）与 `service_name`（默认 Service01）；DVB 选项：`mpegts_transport_stream_id`、`mpegts_original_network_id`、`mpegts_service_id`、`mpegts_service_type`、`mpegts_pmt_start_pid`（默认 0x1000）等，全集见[官方手册](https://ffmpeg.org/ffmpeg-formats.html#mpegts-1)。

### HLS 与 DASH

`hls` 混流器按 Apple HLS 规范把 MPEG-TS（或 fMP4）切段并生成播放列表；输出文件名即 m3u8 名，默认按序号生成 `out0.ts` 等分段。编码时须闭合 GOP 且 GOP 大小与分段时长匹配。示例（官方）：

```sh
ffmpeg -i in.mkv -c:v h264 -flags +cgop -g 30 -hls_time 1 out.m3u8
```

常用选项：`hls_time`（目标分段时长，默认 2 秒）、`hls_init_time`、`hls_list_size`、`hls_flags`（`delete_segments`、`append_list` 等）、`hls_segment_type mpegts|fmp4`（fMP4 分段，init 名用 `hls_fmp4_init_filename`）、`hls_segment_filename`、多码率变体 `var_stream_map`、加密 `hls_key_info_file`。加密需先用脚本生成 key 与 keyinfo 文件，再指定 `-hls_key_info_file file.keyinfo`（亦可用 `hls_enc`、`hls_enc_key`、`hls_enc_key_url` 直接控制）。

解流器 `hls` 把所有变体流呈现为 AVStream，`variant_bitrate` 元数据给出所属变体码率；选项 `live_start_index`、`prefer_x_start`。`dash` 混流器按 ISO/IEC 23009-1 生成 MPD 与分段，段名支持 `$RepresentationID$`、`$Number$`、`$Bandwidth$`、`$Time$` 与 ffmpeg 专有的 `$ext$`；`adaptation_sets` 把流归入适配集。实时 DASH 示例（官方，两档码率）：

```sh
ffmpeg -re -i <input> -map 0 -map 0 -c:a libfdk_aac -c:v libx264 \
  -b:v:0 800k -profile:v:0 main \
  -b:v:1 300k -s:v:1 320x170 -profile:v:1 baseline -ar:a:1 22050 \
  -bf 1 -keyint_min 120 -g 120 -sc_threshold 0 -b_strategy 0 \
  -use_timeline 1 -use_template 1 -window_size 5 \
  -adaptation_sets "id=0,streams=v id=1,streams=a" \
  -f dash /path/to/out.mpd
```

`segment/stream_segment/ssegment` 是更通用的分段器（`segment_time`、`segment_list`、`segment_format_options`，配合 `-strftime` 亦可实现 HLS）；`hds`、`smoothstreaming`、`whip`（WebRTC 亚秒级推流）为其余流媒体形态。选项全集见官方：[https://ffmpeg.org/ffmpeg-formats.html#hls-2](https://ffmpeg.org/ffmpeg-formats.html#hls-2)。

### FLV

`flv` 解流器读取 FLV 文件与 RTMP 网络流；强制格式时直播断流用 `live_flv`。选项：`-flv_metadata`（按 onMetaData 建流）、`-flv_ignore_prevtag`、`-flv_full_metadata`。混流器选项 `flvflags`：`aac_seq_header_detect`、`no_sequence_end`、`no_metadata`、`no_duration_filesize`（直播流收尾时时长/大小为 0 则不写）、`add_keyframe_index`（利于 HTTP 伪流 seek）。

### WAV

解流器：`ignore_length`（忽略 data 块长度读到文件尾，救回头部未更新的残缺文件）、`max_size`（单包上限）。混流器：`rf64` 取 `auto`（超 4GB 自动转 RF64，JUNK 块占位）/ `always` / `never`（默认纯 RIFF，超 4GB 大小字段失效）；`write_bext`（BWF BEXT 块）、`write_peak`（EBU Tech 3285 峰值包络：`off`/`on`/`only`）及 `peak_block_size`、`peak_format`、`peak_ppv`。

### MP3

MP3 混流器写裸 MP3 流，可选特性：开头 ID3v2 头（默认启用，`id3v2_version` 取 3 或 4，0 关闭）；APIC 封面帧（以单包视频流提供，`title`/`comment` 元数据映射为描述与图片类型，注意会缓冲音频直到收齐图片）；ID3v2 之后的 Xing/LAME 帧（默认启用、仅可 seek 输出时写，`write_xing 0` 关闭）；文件尾旧式 ID3v1（`write_id3v1 1` 启用，能力极有限，不推荐）。示例（官方，逐字保留）：

```sh
ffmpeg -i INPUT -id3v2_version 3 -write_id3v1 1 out.mp3
ffmpeg -i input.mp3 -i cover.png -c copy -map 0 -map 1 \
  -metadata:s:v title="Album cover" -metadata:s:v comment="Cover (Front)" out.mp3
ffmpeg -i input.wav -write_xing 0 -id3v2_version 0 out.mp3
```

### OGG

`-page_duration`（微秒，页时长目标：0 尽量填满段、1 近似一页一包，默认 1 秒，权衡 seek 粒度与容器开销）、`-serial_offset`（起始序列号，取不同大值可安全串联 ogg 文件）。

### concat 解流器

从文本清单依次读多个文件，如同全部包已混流；自动调整时间戳使下一文件接在前一文件结尾。所有文件须有相同流（同编解码器、时基等）。指令：`file 路径`（空格用引号/反斜杠转义）、`ffconcat version 1.0`（放首行供自动探测）、`duration`（覆盖文件时长，齐全则可全片 seek）、`inpoint`/`outpoint`、`stream`（选取部分流）。清单示例（官方）：

```text
ffconcat version 1.0
file file-1.wav
duration 20.0
file subdir/file-2.wav
```

## 元数据

FFmpeg 可将元数据导出为 UTF-8 INI 风格文本并经 `ffmetadata` 混/解流器回读：首行 `;FFMETADATA1`，随后 `key=value` 全局标签；`[STREAM]`/`[CHAPTER]` 分节存流/章节标签，章节可带 `TIMEBASE=1/1000`、`START`、`END`；`;`、`#` 行为注释；`=`、`;`、`#`、`\` 与换行须用反斜杠转义。
